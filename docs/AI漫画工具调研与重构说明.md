# AI 漫画工具调研与墨格重构说明

调研日期：2026 年 9 月 13 日。依据各工具官方产品页、官方帮助与开源仓库；没有购买订阅进行画质横评。以下比较的是创作流程与功能，不是实测画质排名。

## 观察到的创作方式

| 工具 | 官方资料展示的主要工作方式 | 对本项目的启发 |
| --- | --- | --- |
| [Dashtoon Studio](https://dashtoon.com/ai-comic-generator) | 从分镜草图组织画面；定义角色外貌与身份；提供局部调整和多种风格 | 固定角色设定，分镜先行，允许针对单格反复修订 |
| [LlamaGen](https://llamagen.ai/text-to-comic) | 将故事或脚本转换为带对白的漫画页；在工作区继续编辑画格、对白与布局 | 用户提供故事材料，先形成可审阅的结构，再转入视觉创作 |
| [Anifusion](https://anifusion.ai/) | 选择漫画布局、描述故事、编辑并下载；提供角色参考、文字、画布与绘图工具 | 创作流程分阶段，文字层与图像层分离，排版和导出是一等功能 |
| [AI Comic Factory](https://github.com/jbilcke-hf/ai-comic-factory) | 开源 LLM 与图像渲染流水线，可配置多种后端；仓库已在 2025 年 10 月归档 | 可参考分镜流水线，但不把旧依赖、多后端配置和运行环境负担带给普通用户 |

从这些资料作出的产品判断：短篇漫画的关键不是把一句提示变成若干张图，而是让创作者控制叙事节奏、人物身份、每格内容和最终阅读顺序。这个判断用于设计墨格，不能据此断言某个工具实际生成质量更好。

## 原版的问题

本地原版以固定角色与固定分镜开场，没有故事纲要或小说生成接口。默认 Mock 只返回 SVG 占位图；文字描述与角色设定被直接拼到单次绘图提示中。作品依赖浏览器 localStorage，没有版本控制和可靠图片文件管理。生成接口缺少超时、取消、结构校验、参考图编辑和按项目互斥；启动还需要 Node.js 与开发服务。

原版 OpenAI 绘图请求把 `response_format` 统一作为生图参数，缺乏针对 GPT Image 的参数处理。这次改为官方 SDK 的 PNG 返回流程，并通过传输层测试校验参数。

## 本次落地

1. **灵感先变成纲要。** 用户决定类型、情绪、格数与风格。GPT 输出一句话故事、背景、冲突、节拍、结尾与角色表。所有字段可修改；只有确认后才能继续生成。
2. **只围绕短篇。** 默认限制 1–3 个核心角色、1–2 个场景、一个主要冲突，要求完成收束。支持 4–12 格片段，不自动续写成长篇。
3. **文稿和漫画可以分别推进。** 小说正文可生成、手写、润色；也可以直接依据已确认纲要生成分镜。
4. **把角色一致性落实为参考输入。** 外貌、服装、道具与性格固定保存。角色可上传参考图或生成设定图；每格调用 GPT Image 时带入出场角色参考和前面的已完成画面。
5. **逐格可控。** 修改景别、场景、动作、情绪、出场角色、对白和视觉说明；重新绘制一格，切换历史图片，而不重做全篇。
6. **文字与图像分开。** 要求图像模型不画字，中文对白由 Canvas 排版，可调整位置；完整保留原图，不用裁切掩盖画面内容。
7. **本地作品管理。** 文件保存、原子写入、修订冲突检测、历史版本、任务日志、图片持久化、完整工程导入导出。
8. **真正的桌面入口。** Electron 独立窗口，内置运行环境，本机随机端口，重复打开聚焦同一个窗口；系统加密密钥，界面中配置与检测连接。

没有在本轮实现自由手绘、任意多边形分格、逐像素蒙版局部修复、漫画视频化和多人协作。它们不影响本次用户要求的短篇纲要到插画的核心流程。对人物一致性不作绝对保证，最终仍需审阅。

## OpenAI 接口依据

- 小说、纲要与分镜使用 Responses API 的结构化输出，校验对象字段、镜头数和角色引用；处理拒绝与不完整返回。依据：[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)。
- 图片使用 Images API：无参考时生成，有参考时走编辑接口。GPT Image 默认返回 base64，存为本地 PNG；没有把文本模型当作 Images 模型。依据：[Image generation](https://developers.openai.com/api/docs/guides/image-generation)。
- 默认使用 `gpt-5-mini` 与 `gpt-image-2`，均保留可编辑模型名，账户可用性通过连接检测辅助检查。依据：[GPT-5 Mini](https://developers.openai.com/api/docs/models/gpt-5-mini)、[GPT Image 2](https://developers.openai.com/api/docs/models/gpt-image-2)。
- GPT Image 2 对参考图不发送可调 `input_fidelity`；GPT Image 1 / 1.5 的参考图请求使用高保真设置。依据仍为官方图片生成指南。

桌面安全设计参照 [Electron Security](https://www.electronjs.org/docs/latest/tutorial/security) 与 [safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)：渲染进程不开放 Node.js，启用隔离与沙箱，限制导航，API 只监听本机，已保存密钥不返回前端，也不写入作品工程。

## 验证范围

已使用隔离测试服务验证：故事生成到确认、正文、人物参考图、分镜、批量绘制、重绘、失败后只补缺失画格、取消、并发写入保护、历史恢复、携图工程导出导入、PNG/PDF 导出与窄窗口排版。

OpenAI SDK 传输层使用模拟响应检查结构化请求、PNG 生成参数、多参考图 multipart 请求与 429 不自动重试；不把这些测试视为真实模型画质验证。测试中的图片为明确隔离的本地测试素材，正式程序不会显示测试工程。

真正的桌面窗口已验证启动、隔离、Windows 加密保存密钥、退出重启后恢复密钥与作品。由于项目未提供有效 OpenAI API 密钥，本轮没有执行真实付费文稿或插画生成。配置密钥后可用「四格片段 + 草稿质量」进行首次实际创作。
